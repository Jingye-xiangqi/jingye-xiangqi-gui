skin.json 格式说明（给「皮肤批量转换脚本」用）
============================================================

每个皮肤文件夹（skins\皮肤名\）里放：

    background.png        桌面背景图（整块棋盘区域都用它，每套风格不同）
    board.png             可选：棋盘图（有就把棋盘画成这张图；没有就用背景 + 程序画的格线）
    ba.png bb.png ...     14 个棋子图（圆形居中，建议透明背景）
    ra.png rb.png ...
    mask.png mask2.png    可选：选中框 / 落点提示框（没有就用程序自带的）
    skin.json             对齐参数（本文件说明的就是它）

程序读 skin.json 的方式：**根据参数算出"棋盘网格"应该画在背景的什么位置**，
把 8×9 的格线画在那里，棋子按"格子 × pieceScale"贴到交叉点中心。
所以只要参数给对了，不管皮肤的边距比例是多少，都不会错位。


一、当前批量转换用的写法（推荐，比例式）
------------------------------------------------------------
{
  "board_w_ratio": 1.0,
  "board_h_ratio": 1.0,
  "margin_left": 0.0,
  "margin_top": 0.0,
  "grid_w": 0.8,
  "grid_h": 0.8
}

  margin_left / margin_top   网格左上角的位置（占背景图宽/高的比例，0~1）
  grid_w / grid_h            网格的大小（占背景图宽/高的比例，0~1）
                             例：grid_w=0.8 表示棋盘宽 = 背景宽的 80%
  board_w_ratio / board_h_ratio  棋盘区域占整块画布的比例（1.0 = 铺满，默认）

程序的实际做法：背景图铺满整个棋盘区域（拉伸到画布，不裁切、不留黑边），
然后按上面的比例算出网格位置；再自动保证四周留出约 0.6 格边距
（放坐标、避免边上的棋子被裁掉），必要时把棋盘整体往中间挪一点点，尺寸不变。
格线颜色会根据背景明暗自动选（深色背景用浅色线，浅色背景用深色线）。


二、另一种等价写法：直接给"棋盘图里网格的像素位置"（有 board.png 时用）
------------------------------------------------------------
{
  "board": "board.png",
  "grid": [59, 79, 560, 630],
  "pieceScale": 0.92
}

  board      棋盘图文件名（默认找 board.png / board.bmp / board.jpg…，可省略）
  grid       棋盘图里 **8×9 网格** 的位置，[x, y, w, h]
             x, y  = 网格左上角（最上面那条横线、最左边那条竖线的交点）在图片里的像素坐标
             w, h  = 网格的宽和高（＝最右竖线 − 最左竖线，最下横线 − 最上横线）
  pieceScale 可选，棋子图大小 = 格宽 × 这个数（默认 0.92，一般不用改）

  ★ 如果这张 board.png **里面没有完整的 8×9 网格**（图被放大过或只截了棋盘的一角），
    就把 grid 去掉，改成写：
        "board_grid_usable": false
    程序看到这个就会**不用这张图当棋盘底**，改为"程序自画棋盘 + 这套皮肤的材质配色"
    （把 board.png 缩到很小再放大，细格线被平均掉、只留材质与颜色），棋子仍然用本皮肤。
    自带的 78 套皮肤里有 17 套属于这种情况，skin.json 里就是这么写的。


三、grid 还可以写成这些等价形式（程序都认，挑一种最方便的）
------------------------------------------------------------
1) 左上角 + 宽高（对象写法）
   "grid": {"x": 59, "y": 79, "width": 560, "height": 630}

2) 四条边（左上右下）
   "grid": {"left": 59, "top": 79, "right": 619, "bottom": 709}

3) 左上角 + 右下角
   "grid": [[59, 79], [619, 709]]

4) 用比例（0~1，相对图片宽高）：数值都 ≤ 1.5 时程序按比例理解
   "grid": [0.0656, 0.079, 0.6222, 0.63]
   （900×1000 的图里 0.0656×900≈59，0.63×1000=630）

5) 边距 + 一格像素
   "margins": {"left": 59, "top": 79, "right": 281, "bottom": 291},
   "cell": 70
   （right / bottom 是"网格右边到图片右边"的边距）

6) 左上角 + 一格像素
   "origin": [59, 79], "cell": 70
   （cell 也可以写成 [cellX, cellY] 或 {"x": 70, "y": 70}）

键名不区分大小写、下划线和连字符：
   grid / gridRect / grid_rect / boardRect / board_rect / rect / area /
   boardArea / gridBox / frame 都当作网格位置。


三、可选的两个微调（一般不需要）
------------------------------------------------------------
{
  "adjust": {"dx": 0, "dy": 0, "scale": 100}
}
  dx / dy  整体平移，单位是"格"（0.1 就是挪十分之一格）
  scale    整体缩放百分比（100 = 原样）
  背景：极个别皮肤如果网格线不是标准 8×9（比如带额外边框装饰），
        可以用这两个值微调；正常情况下留空即可。


四、程序的容错规则（写错了也不会崩）
------------------------------------------------------------
· skin.json 不存在、读不动、或者里面的参数明显不对（格子不是方的、
  网格超出图片范围、网格占图片不到 1/4）→ 程序会自动检测棋盘图里的网格；
· 写了 "board_grid_usable": false，或者自动检测发现这张图的网格根本装不下 8×9
  → 改用"程序自画棋盘（格线绝对准）+ 该皮肤 board.png 的材质配色"（棋子照样用本皮肤）；
· 连 board.png 都没有 → 用 background.png 中间提亮一块当棋盘面，格线按 skin.json 的比例画；
· 具体走了哪条路，会写在 exe 旁边的 link_debug.log 里，例如：
    皮肤：1-Ivory｜棋子 16 张｜棋盘图 有｜对齐参数 skin.json
    棋盘：木质暗木 的 board.png 里没有完整的 8×9 网格（图被放大或裁切过），
          改用自带棋盘底 + 该皮肤材质配色，棋子仍然用本皮肤。
· 转换脚本只要保证 grid 给对，78 套棋盘都能正确对齐。


五、自带 78 套皮肤是怎么校准出来的（供参考）
------------------------------------------------------------
校准程序逐套读 board.png：
  1) 8×9 网格必须完整落在图内，而且格子必须是正方形 —— 用同一个格宽同时约束
     横竖两个方向，这样"半个周期"的错解不会胜出；
  2) 再对横竖各做一次 ±10% 的微调（有些棋盘图被拉伸过几个百分点）；
  3) 逐条检查 9 条竖线 + 10 条横线是否真的压在图的线上，给出"命中率"。
校准结果直接写进每套的 skin.json（grid 字段），所以运行时**不用再检测**，
打开就是对齐的。你新做的皮肤如果懒得量，也可以先不写 grid，让程序自动检测。


六、怎么快速自检
------------------------------------------------------------
1. 打开程序 → 顶部「界面」→「棋子皮肤」区域：
     旁边会显示 skins 目录的路径和"共 N 套"；
     下拉框里选中某一套 → 棋盘立刻变成这套的棋盘图，棋子也换成这套的样式。
2. 看棋盘边缘：四个角的棋子应该正好压在棋盘图的四个角上；
   如果整体偏了，用 skin.json 的 adjust 微调（或检查 grid 是否量的是网格线交点）。
3. 点「刷新」可以重新扫描 skins 目录（转换脚本边跑边刷新即可看到新皮肤）。


（静夜象棋界面 · 皮肤说明）

============================================================
棋子 / 棋盘的对齐是怎么保证的（2026-09-26 自动校准）
============================================================

一、程序会**核对**棋盘图里的网格，而不是盲信 skin.json
------------------------------------------------------------
界面上要贴一张皮肤的 board.png 当棋盘时，程序先看图里那 9 条竖线、
10 条横线到底在哪（在 skin.json 给的参数附近找，逐线定位 + 等间距拟合），
然后分三种情况处理：

  1. 测得出、而且每条线都在等间距网格上（内部线偏差 ≤ 2px、最外圈 ≤ 3.2px）
     → 用**校准后**的网格贴图：格线和棋子严丝合缝；
  2. 测不出（图里没有格线 / 线条太弱 / 不是等间距）
     → **沿用 skin.json 里写的参数**（改坏了不如不改）；
  3. skin.json 里既没有网格、也没有比例，或者写了 board_grid_usable: false
     → 改用**程序自画棋盘**（格线 100% 准）+ 这张皮肤的材质配色 + 这套棋子图。

自带 78 套皮肤里：57 套是第 1 种（用自己的棋盘图，参数已自动校准），
21 套是第 3 种（棋盘图里没有完整网格，本来就是程序画棋盘）。

二、grid 写成对象最保险（列表有两种解释）
------------------------------------------------------------
   "grid": [47, 58, 416, 477]

这 4 个数字既可能是 [左上角 x, y, 宽, 高]，也可能是 [左, 上, 右, 下]。
程序两种都会试（挑和真实线条对得上的那种），但**推荐直接写清楚**：

   "grid": {"x": 47, "y": 58, "w": 416, "h": 477}       # 左上角 + 宽高
   "grid": {"left": 47, "top": 58, "right": 463, "bottom": 535}

本工具（tools/calibrate_skins.py）自动写入的就是对象写法，不会有歧义。

三、几个可以手写的开关
------------------------------------------------------------
   "board_grid_usable": false   这张棋盘图里没有完整 8×9 网格 → 用程序自画棋盘
   "board_grid_usable": true    正常贴这张棋盘图（默认）
   "board_grid_force": true     强制按 skin.json 的 grid 贴图，程序不再核对
                                （只在你自己量过、很有把握时用）
   "pieceScale": 0.92           棋子直径 = 格宽 × 这个数（默认 0.92）

四、棋子一定是"圆心压在交叉点上"
------------------------------------------------------------
棋子图会被程序先按**内容框**（去掉四周透明边）裁成正方形再缩放，
所以哪怕原图留的透明边不匀、棋子画得偏一点，圆心也一定落在交叉点上。
