# 静夜象棋界面 1.6（Jingye Xiangqi）

从零实现的中国象棋打谱 / 训练 / 人机对战程序：完整棋盘界面 + 皮卡鱼（Pikafish）
UCI 引擎 + XQF/PGN 棋谱 + 变例记录 + 局面分析与思考过程可视化。

界面是**原生桌面窗口**（Tkinter 实现，不需要浏览器、不需要联网），
**只依赖 Python 标准库，无需安装任何第三方包**。

```
python desktop_app.py
```

双击 exe（或运行上面的命令）就会弹出一个独立的象棋窗口；关闭窗口即退出。
仓库里还保留了可选的浏览器界面（`python run.py`，或 exe 加 `--web` 参数）。

> 版本：**1.6**　窗口标题：`静夜象棋界面1.6（QQ:3375227582）`
> 完整开发过程与每一次 bug 修复记录见 [`更新日志.txt`](更新日志.txt)；
> 面向普通用户的操作说明见 [`使用说明.txt`](使用说明.txt)。

## 2. 运行环境

* Python 3.9 及以上（推荐 3.10+；开发与测试使用 3.13），需带 tkinter（官方安装包默认包含）
* 象棋引擎：皮卡鱼 Pikafish（Windows/Linux/macOS 均可），**需要与 `pikafish.nnue`
  权重文件放在同一目录**（官方发行包已包含）

```bash
python desktop_app.py                        # 原生桌面窗口（推荐）
python desktop_app.py --engine D:/Pikafish/pikafish.exe   # 指定引擎
python desktop_app.py --threads 8 --hash 512 # 预设引擎资源
python desktop_app.py --web                  # 改用浏览器界面（可选）
python run.py                                # 浏览器界面（开发用）
```

如果拿到的是打包好的单文件 exe，直接**双击 `静夜象棋界面.exe`** 就行：
它会直接弹出原生象棋窗口（不经过浏览器），关闭窗口即退出程序。
把 `pikafish.exe` 与 `pikafish.nnue` 放在 exe 同一个文件夹里，程序会自动找到并加载。

启动时会自动在常见位置查找皮卡鱼（PATH、程序目录、`engine/`、桌面、下载目录等），
没找到也不影响使用，可稍后在界面里手动选择。

## 3. 界面导览

**界面布局（v2.4 起，参考鲨鱼象棋的简明风格）**

```
┌─ 顶部工具栏（一行，靠左）────────────────────────────────────────────────────┐
│ 新建棋局 打开棋谱 保存棋谱 │ 首 上一步 播放 下一步 末 悔棋 重做 │
│ 引擎执红 引擎执黑 分析模式 │ 编辑局面 复制FEN 翻转棋盘 │ 引擎设置 开局库设置 │ ☑音效 │ 模式徽标 │
├────────────┬────────────────────────────────┬────────────────────────────┤
│ 开局库/云库 │            棋  盘              │  棋谱列表（着法树 + 评注）   │
│ （标签页，   │      （最大，视觉中心）         │  ───────────────────────   │
│   上下两栏） │                                │  引擎分析（评分/胜率/推荐）  │
└────────────┴────────────────────────────────┴────────────────────────────┘
│ 状态栏：提示信息 │ 引擎状态 │ 分析深度与评分                                  │
```

* **引擎设置**、**开局库设置**都是按钮，点开才弹出对话框，平时不占界面空间；
  引擎设置对话框里只有「引擎路径」和该引擎自己声明的 UCI 选项；
* 右栏分析面板顶部有一行小控件：**思考（秒）/ 深度 / 路线**（人机对战与分析的搜索范围）；
* 编辑局面时，棋盘下方会出现一条棋子调色板（选子→点棋盘落子／「擦」清除／
  清空棋盘／初始局面／交换红黑／红先黑先／FEN 粘贴应用）；
* 棋盘下方一行显示当前行棋方、手数、子力与重复局面；
* 左右两栏的表格与列表都可以双击使用：双击库着/云库着法或推荐着法即走这步，
  双击棋谱列表中的着法即跳转（右键可设为主线/删分支）。

**三种模式（窗口顶部第二行，三个大按钮；互斥单选，且都可以取消）**

| 选择 | 谁走棋 | 行为 |
| --- | --- | --- |
| **都不选（默认）** | 双方都由你走 | **纯手动打谱**：引擎不自动走子、也不强制分析；想分析时点「开始分析」（或 F5），分析会跑完不会被打断 |
| **引擎执红** | 引擎走红方、你走黑方 | 轮到红方时引擎自动走棋；棋盘自动翻成"黑方在下"方便你操作 |
| **引擎执黑** | 引擎走黑方、你走红方 | 轮到黑方时引擎自动走棋；棋盘红方在下 |
| **分析模式** | 双方都不自动 | 引擎**一直持续分析**（不限时间），局面一变立刻重算，实时给出最佳着法、评分、胜率与胜率变化曲线；点「走这步」可自己走推荐着法，也可自由摆棋研究变例 |

* 当前模式用**深红底白字**高亮，右侧另有徽标显示「引擎执红　轮到你走 / ⏳ 引擎思考中…」；
* **再次点击当前模式即可取消**（按钮变回未选中），回到纯手动打谱；三个模式互斥，随时可切换：
  切到「引擎执红 / 执黑」时，如果正好轮到引擎，它会立刻开始走棋；
* 「分析模式」是独立的一项，可以单独开关，不需要先选执红 / 执黑；
* 引擎执红 / 执黑时不能替引擎落子（会提示"现在是引擎走棋"）；分析模式则随时可以走任意一方。

```
┌──────────────────────────── 顶栏 ────────────────────────────┐
│ 静夜象棋界面 │ 打谱复盘 / 局面分析 / 人机对战 │ 记谱 · 新建 · 导入 · 导出 · FEN · 翻转 │
├───────────────┬──────────────────────────────────────────────┤
│               │  棋谱 │ 分析 │ 引擎 │ 局面                       │
│     棋盘       │                                              │
│               │  （棋谱树 / 推荐着法 / 引擎设置 / FEN 与信息）  │
├───────────────┤                                              │
│ 首 上 ▶ 下 末    │                                              │
└───────────────┴──────────────────────────────────────────────┘
```

* **棋盘**：点击棋子选中（绿点＝可走，红圈＝可吃），再点击落点即走子；也可以直接拖拽。
  右上角「翻转棋盘」切换红黑视角。
* **棋谱页**：着法树。主线平铺，变例缩进显示；鼠标移到某手上会出现「主线 / 删除」按钮。
  下方可写当前着法评注。
* **分析页**：引擎思考过程。评分从红方视角显示（正数表示红方好），
  下面有 WDL 概率条、评分曲线、红方胜率变化曲线和多条推荐路线，
  点行看箭头、点「走这步」直接上盘。
* **开局库页**：加载 OBK / 云库文件，列出当前局面的命中招法与权重、胜率、次数；
  内含两个标签页：

  * **开局库**：只接受 **PFBOOK / OBK / XQF** 三种格式（其它格式会弹提示拒绝）；
    可以「用当前棋谱建库」并「导出 OBK」；勾选「优先走库着」后人机对战会走库中着法；
    勾选「同时显示云库结果」时，云库命中会合并到同一张表（来源列区分为「云库」）。
  * **云库**：接入**中国象棋云库 chessdb.cn**，在线查询当前局面的
    着法 / 分值 / 胜率 / 排序 / 备注（未收录的着法会标注「未收录」），
    并显示云库最佳着法；可开关、手动刷新、清空缓存；勾选「人机对战时优先走云库着法」后，
    本地库没命中时引擎会先走云库着法（带磁盘缓存，重复局面秒回）。
* **引擎设置（弹窗）**：只有两样东西 —— **引擎路径**（浏览 / 自动查找 / 加载 / 卸载 /
  重新探测选项）和**该引擎自己声明的全部 UCI 选项**（按引擎回应动态生成，改完立即生效，
  按引擎分别记住）。皮卡鱼会列出 11 项：`Debug Log File`、`NumaPolicy`、`Threads`、`Hash`、
  `Clear Hash`、`Ponder`、`MultiPV`、`Move Overhead`、`nodestime`、`UCI_ShowWDL`、`EvalFile`；
  换别的引擎就换成那一套选项，界面不写死。
* **内置皮卡鱼**：引擎（`pikafish-bmi2.exe` + `pikafish.nnue`）随 exe 一起打包在
  `engine/` 目录里，**第一次打开就自动从 `sys._MEIPASS` 加载**，用户不需要另外放引擎文件。
  手工选择引擎的功能完全保留：点「浏览…」可以换成任意 UCI 引擎，程序会记住这个选择并在
  下次启动时优先用它；选择的引擎文件不在了就自动回退到内置皮卡鱼。内置引擎在配置里用
  稳定标记 `@builtin/<文件名>` 记录（onefile 每次运行的临时解包目录都不同，不能直接写路径），
  所以它的 UCI 选项跨次启动也不会丢。
* **局面信息**：FEN 读写、行棋方、子力统计、重复局面、棋谱信息与导入提示，
  以及**编辑局面**（自由摆子 / 清空 / 初始局面 / 交换红黑 / 先行方）；
  音效开关在顶部工具栏最右侧，「思考 / 深度 / 路线」在右栏分析面板顶部。

## 4. 打谱训练

### 导入

点顶栏「导入棋谱」，支持：

* `.pgn`：象棋 PGN。文件里可以有多局（导入后自动载入第一局）；
  着法支持 ICCS（`h2e2`）、WXF（`C2.5`、`H2+3`）与中文记谱（`炮二平五`、`馬２進３`）；
  注释 `{...}`、`;` 行注释、括号变例 `(...)` 都会保留。
  编码自动识别 UTF-8 / GB18030（中文棋谱站多是 GB18030）。
* `.xqf`：象棋演播室二进制棋谱，按格式规范完整解析（密钥推导、棋盘置换、着法异或、
  注释与变例），新版（版本号 > 0x0A）与旧版都支持；遇到坏着会记入「局面」页的导入提示而不是中断。

### 回放与变例

* ⏮ / ◀ / ▶ / ⏭ 逐手前后，或点「▶ 自动播放」按设定间隔连续播放（空格键也能暂停）。
* 在任意历史局面直接走子即可**形成新变例**（已有同样着法时自动进入该分支，不重复添加）。
* 变例可「设为主线」或「删除分支」；每个节点都能写评注，导出时写进 PGN。
* 导出：「导出 PGN」按当前记谱样式（中文 / 繁体 / 坐标 / WXF）写出，含变例与评注。

## 5. 引擎与难度

* 引擎通过标准 UCI 协议驱动：`uci` 握手 → 读取选项 → `setoption` → `position` → `go` /
  `stop`，解析 `info`（深度、评分、节点、NPS、WDL、PV）与 `bestmove`。
* **引擎设置只放引擎自己的东西**（v2.5 起）：加载引擎时把 `uci` 回应的所有
  `option name ...` 收集起来，按类型动态生成控件 —— `spin` 数字框、`check` 勾选框、
  `combo` 下拉框、`string` 输入框、`button` 按钮 —— 改一个就立刻 `setoption`。
  界面里不写死任何选项名，皮卡鱼、象眼、其它 UCI 引擎各显示各自的一套；
  选项值按引擎分别保存，下次加载自动恢复。
* **搜索范围**（程序发给引擎的 `go` 参数）在右栏「分析」面板的一行小控件里：
  `思考` 秒数 → `go movetime`、`深度` → `go depth`（0＝不限）、
  `路线` → 引擎的 `MultiPV` 选项（1-12，默认 3）。
* **人机对战的棋力**由引擎自己的选项（`Threads` / `Hash` 等）加上这两个搜索范围决定；
  皮卡鱼新版没有 `UCI_LimitStrength` / `UCI_Elo`，所以想让它"更弱"就把思考时间调小。
* 如果引擎支持 `Skill Level`、`UCI_LimitStrength`、`UCI_Elo` 等选项，
  它们会自动出现在「引擎设置」的选项列表里，可以随时调整。
* 分析模式的持续搜索（不限时间）由顶部「分析模式」按钮 + 「开始分析 / 停止分析」控制。

## 6. 目录结构

```
静夜象棋界面/
├── 静夜象棋界面.exe        打包好的单文件程序（双击即用）
├── desktop_app.py          桌面版入口（原生窗口；--web 可切回浏览器版）
├── run.py                  浏览器版启动脚本（开发/备用）
├── requirements.txt        无第三方依赖（说明用）
├── xqtrainer/
│   ├── board.py            规则内核：FEN、走子生成、合法性、将死/困毙
│   ├── notation.py         ICCS / WXF / 中文记谱 的生成与解析
│   ├── game.py             棋谱树、变例、PGN 导入导出
│   ├── xqf.py              XQF 二进制棋谱读取
│   ├── engine.py           UCI 引擎封装（子进程 + 解析 + 容错）
│   ├── session.py          会话层：局面状态、分析、人机对战编排
│   ├── ui/                 原生界面：board_view.py（棋盘画布）+ app.py（主窗口）
│   ├── server.py           可选：本地 HTTP + SSE 服务（浏览器版用）
│   └── web/                可选：浏览器界面（index.html / style.css / app.js）
├── engine/                 引擎（皮卡鱼 + 权重 + 许可）
├── assets/  tools/         程序图标与图标生成脚本
└── tests/                  自动化测试（标准库 unittest）
```

架构上后端是唯一权威：界面不自己算棋，只负责显示与交互，
所有走子、合法性、记谱、引擎通讯都在 Python 层完成。
原生界面对引擎事件用「队列 + 定时轮询」的方式回到主线程，因此引擎再忙也不会卡住界面
（浏览器版则用 SSE 限频推送）。

### 7.1 连线的坐标系（分辨率 / DPI 适配）

连线要同时跟三个坐标系打交道，改 `xqtrainer/link.py` 前先看这一段：

1. **我们看到的客户区坐标**：本程序 DPI **不感知**（Tkinter 默认），所以 Windows 会把
   所有接口（`GetClientRect` / `ClientToScreen` / 截图）按 `系统DPI ÷ 96` 虚拟化。
   1080p + 100% 缩放时相当于没缩放，2K + 150% 时我们看到的尺寸是物理尺寸的 2/3。
2. **截图坐标**：识别器给出的棋盘网格 `(x0, y0, 格宽, 格高)` 是**截图**里的像素。
   它和客户区尺寸可能不相等（DPI 虚拟化、有些客户端自己按物理像素渲染），
   由 `GraphLinker._to_client_grid()` 按 `客户区 ÷ 截图` 换算。
3. **目标窗口自己的客户区坐标**：`PostMessage` 的鼠标坐标 Windows **不做任何换算**，
   DPI 感知的客户端按物理像素解释。系数由 `compute_message_scale(我方感知, 对方感知,
   目标DPI, 系统DPI)` 计算：我方不感知、对方感知时 = 系统DPI÷96（2K/150% 就是 ×1.50），
   两边感知级别相同就是 ×1.00。

所以整条链路是：截图 → 识别网格 → `_to_client_grid`（→客户区坐标）→ `_client_point`
（ICCS → 客户区坐标，含执黑时的 180° 换算）→ `Win32.click` 乘 `message_scale` 后发消息。
每一步都会在 `link_debug.log` 里留痕（`连线环境：…｜消息坐标系数=…｜已点击 …｜坐标系数 ×…`），
排查时先看这几行。屏幕的实际分辨率用 `GetDeviceCaps(DESKTOPHORZRES/DESKTOPVERTRES)` 取
（`GetSystemMetrics` 在 DPI 不感知时只给逻辑分辨率）。

## 8. 已知限制

* **判罚规则**：实现了走子合法性、将死、困毙与三次重复局面的提示，
  但没有完整实现中国象棋竞赛规则里"长将 / 长捉 / 长兑"的长打判罚（需要走子历史裁决），
  对打谱训练影响不大；界面上会提示重复局面次数，由使用者判断。
* XQF 只读（不写回），CBF/CBR 未支持。
* 引擎选项里的文件类选项（例如 `EvalFile`）需要填绝对路径；
  如果皮卡鱼的 `.nnue` 与可执行文件同目录，引擎一般会自动找到。
* 原生界面基于 Tkinter：皮肤以矢量绘制为主，暂不支持载入外部棋盘/棋子图片（规格见第 11 节）。
  浏览器界面（`--web`）为可选备用方式。

## 9. 常见问题

**引擎加载失败 / 提示缺少 NNUE**
确认选择的是可执行文件（`pikafish.exe`），且 `pikafish.nnue` 在同目录；
启动失败的原因会显示在「引擎」页的提示区。

**引擎不动 / 一直显示"思考中"**
程序会自动识别引擎是否拒绝该局面（例如摆出了不可能出现的局面），
并中止搜索、在状态栏提示错误；也可以点「引擎」页的「让引擎立即走一步」手动触发。

**喜欢用浏览器界面**
运行 `静夜象棋界面.exe --web`（或 `python run.py`）即可切回浏览器版；
端口被占用时程序会自动改用下一个空闲端口。

**分析时感觉界面迟钝**
在「引擎设置 → 引擎自身选项」里把 `Threads` 调小（例如 4）、`MultiPV` 调小（1-3），
或把右栏的「思考」秒数调小；不要用「分析模式」长时间挂着。程序内部已对引擎输出做限频处理。

**想让人机对战更强 / 更弱**
棋力由**引擎自己的选项**和右栏的搜索范围决定：在「引擎设置」里加大 `Threads` / `Hash`，
在右栏把「思考」秒数调大（例如 5 秒）、「深度」填 0＝不限；想让它弱一点就把秒数调到 0.5-1 秒。

**棋谱中文显示成乱码**
导入时程序会自动尝试 UTF-8 与 GB18030；如果仍有问题，请把文件另存为 UTF-8 再导入。

## 11. 界面素材说明（棋盘 / 棋子图片）

**当前的棋盘与棋子完全由程序矢量绘制，不含任何图片素材**：

* 棋盘：木纹底色用 CSS 渐变生成，网格、九宫斜线、兵炮位标记、楚河汉界文字都是 SVG 线条/文字；
* 棋子：圆形牌面用 CSS 径向渐变 + 内外描边画成，棋面汉字用系统楷体渲染
  （`KaiTi / STKaiti / SimSun / Noto Serif CJK` 依次回退），红黑分色。

这样做的好处是：任意分辨率都清晰、体积为零、可随时切换简体/繁体、缩放不糊。
如果希望更"实体化"的观感（例如专业比赛棋盘、木质/玉石棋子、照片或 3D 渲染棋子），
需要额外的图片素材，规格建议如下：

| 素材 | 数量 | 建议规格 | 说明 |
| --- | --- | --- | --- |
| 棋盘底图（木纹/布面/竹席等） | 每种风格 1 张 | PNG，比例 **9:10**，长边 ≥ 2000px（如 1800×2000） | **只出纹理，不要画网格线**，线条仍由程序绘制以保证格点严格对齐；若底图自带线条，需要同时提供交点坐标 |
| 棋子面图 | 每套 14 张（红黑各 7 枚） | PNG **透明背景**，1:1 正方形，边长 ≥ 256px（推荐 512px） | 牌面居中约占画面 90%，不要自带投影（阴影由程序统一添加），俯视视角 |
| 棋子名：红方 | 7 张 | `帅 仕 相 马 车 炮 兵` | 命名建议 `piece_red_K.png`、`piece_red_A.png`、`piece_red_B.png`、`piece_red_N.png`、`piece_red_R.png`、`piece_red_C.png`、`piece_red_P.png` |
| 棋子名：黑方 | 7 张 | `将 士 象 马 车 炮 卒` | 命名建议 `piece_black_k.png` … `piece_black_p.png`（小写字母对应黑方） |
| 程序图标（可选） | 1 个 | `.ico`，含 16/24/32/48/64/128/256 多尺寸 | 也可只给 512×512 PNG，我用脚本转 ico |
| 字体（可选） | 1 个 | `.ttf` / `.otf`，需允许商用 | 若希望棋面用特定书法字体 |
| 音效（可选，非图片） | 2-3 个 | `.mp3` 或 `.wav`，各 < 100KB | 落子、吃子、将军提示音 |

更省事的替代方案：给一套**已有的成品棋盘+棋子截图**（例如某款界面的大图），

拿到素材后我会做成可在界面里切换的"皮肤"（棋盘底图 + 棋子图 两套资源），
并保留现在的矢量样式作为默认皮肤（图片缺失时自动回退，不会白屏）。

**开局库格式说明**

* **格式规范（本轮明确）**：加载开局库只允许 **PFBOOK / OBK / XQF** 三种格式，
  文件对话框也只过滤这三种后缀；其它后缀（txt / json / bk / pgn / wxf 等）一律拒绝并弹提示。
  若某个 `.xob` / `.bk` 文件本身是 OBK 结构，重命名为 `.obk` 即可加载。
* **OBK**（象棋巫师 / MoonRiver，`.obk`）：128 字节头 + 两段按 64 位哈希升序排列的
  记录数组（每条 8 字节 key + 2 字节出现次数）。哈希算法与 1260 个常量见
  `xqtrainer/data/obk_hash.py`（常量取自 MIT 许可的 MoonRiver Xiangqi Opening Book）。
  本实现已用参考实现里写死的起始局面哈希（6665246470371296167）以及一个真实 OBK 库做过校验：
  开局能匹配出「炮二平五 248 次、兵七进一 93 次…」，走完炮二平五后能匹配出「马8进7 70 次…」。
* **PFBOOK**（鹏飞象棋开局库，`.pfbook`）：鹏飞象棋的私有格式、没有公开规范。
  本程序按"结构探测"处理：先尝试按 OBK 同构解析（128 字节头 + 哈希记录，签名不同也能认），
  再尝试按棋谱结构解析；都不匹配时给出明确提示（并建议改用 OBK 或把棋谱建成库后导出 OBK），
  不会静默失败。
* **XQF 棋谱库**（`.xqf`）：把 XQF 棋谱当作开局库加载，程序按棋谱统计出每种着法的胜/和/负与出现次数。
* **棋谱建库**：导入棋谱后点「用当前棋谱建库」即可聚合出开局库（统计胜/和/负与次数），
  再点「导出 OBK…」就能得到自己的 OBK 库文件。
* **云库数据**：来自中国象棋云库 chessdb.cn 的 `chessdb.php?action=queryall`
  （接口文档：http://www.chessdb.cn/cloudbook_api.html）。程序默认带 `learn=0`
  （不自动学习、不向云库提交数据）、请求限流、内存 + 磁盘缓存（`%TEMP%\jingye_xiangqi_cloud_cache.json`），
  并且只在你勾选「启用云库」时才联网。

**棋谱格式规范（本轮明确）**

* 打开 / 保存棋谱**只允许 XQF 与 PGN** 两种格式，对话框只过滤这两种后缀；
  其它格式（含 WXF 文件、CBF/CBR 等）会弹提示拒绝（PGN 内部仍支持 ICCS / WXF / 中文记谱三种着法写法）。

### v2.0（本次）

**界面改造**

* 全新**原生桌面窗口**（Tkinter 实现）：双击 exe 直接弹出象棋窗口，
  不再打开浏览器、不需要网络；棋盘、棋谱、分析、引擎、局面都在一个窗口里。
* 棋盘画布支持走子动画、拖拽走子、落点提示、将军闪烁、推荐着法箭头、翻转视角。
* 顶栏新增「关于」对话框；新增菜单式播放控制（首/上/播放/下/末）与快捷键。
* 浏览器界面保留为可选方式（`--web` 参数或 `python run.py`）。
* 程序统一命名为**静夜象棋界面**（窗口标题、exe 名称、桌面文件夹、文档一致）。

**自检发现并修复的问题**

1. **终局结果方向写反**：将死时导出的 PGN 结果标签 `1-0` / `0-1` 与实际胜负相反
   （`Board.result()` 返回的是胜方，导出逻辑误当成负方）；
2. **MultiPV 只显示第一条推荐**：界面限频把同一深度紧挨着发出的第 2、3 条路线整批丢弃，
   现已按"每条推荐线独立限频"处理，并补了回归测试；
3. **引擎拒绝局面时界面永久"思考中"**：皮卡鱼会对不可能的局面回
   `CRITICAL ERROR ... Unsupported position` 并拒绝搜索，现在会捕获该提示、中止搜索并给出错误；
   同时加了看门狗（搜索 15 秒无任何输出即中止），避免引擎卡死时界面假死；
4. **没有悔棋**：新增 `Session.undo()` 与界面「悔棋」按钮（人机对战默认退到自己走棋的局面，
   支持 Ctrl+Z），并保证悔棋会中止引擎正在进行的思考；
5. **不可能局面的 FEN 校验**：手工摆出"兵在底线""相过河""士出九宫""棋子数量超标"等
   不可能局面时，现在会明确拒绝并给出原因（这类局面引擎也会拒绝，之前会导致分析异常）；
6. **多局 PGN 无法切换**：新增对局下拉框与 `Session.select_game()`，可在一局文件里切换查看；
7. **关闭窗口后残留定时器报错**：窗口销毁后仍在触发的 `after` 回调现在会被取消，
   动画与防抖任务也会一并清理；
8. **拖拽/点击的一致性问题**：拖拽未被识别的落点会正确复位棋子；选中态与落点提示
   在拖拽过程中保持同步。

**新增的验证手段**（见第 7 节）

* 与皮卡鱼 `perft` 对拍走子生成（13 个局面完全一致）；
* 随机对局 / 随机棋谱树的性质测试（FEN、记谱、PGN、XQF 往返）；
* 原生界面的自动化交互测试（真实鼠标事件驱动窗口）。
